游客与登录 / 两种访问模式

首次打开直接进入游客阅读，不强制登录。用户可在“我的 → 站点账号”分别登录 V2EX 和 Linux.do；登录其中一站不影响另一站。首版同时规划游客阅读与可选账号登录，发帖、回复和站内同步仍按后续范围实施。

能力游客已登录
浏览主题与评论读取站点允许匿名访问的内容。根据该账号实际权限读取；登录不代表获得全部内容。
稍后读 / 阅读进度 / 设置完整支持，保存本机游客空间。保存对应账号空间，不自动同步到社区；游客数据仅经用户主动选择后复制。
受限内容展示登录提示，允许取消并继续浏览公开内容。权限不足说明原因；保留原站打开入口。
退出与失效保持游客阅读。退出立即移除凭据、账号私有正文及图片缓存；失效时停止账号请求，提供重新登录或切回游客。

身份状态与请求隔离

每站独立：guest → authenticating → authenticated → expired
取消登录：回到原状态；网络中断不直接判为登录过期。
仅在凭据失效已确认时标记 expired；403 可能只是内容权限不足。
SessionManager：获取身份、发起登录、校验凭据、退出、发布身份变化。
请求与缓存身份：site + principalId（guest 或账号 ID）+ resourceKey。
身份切换：递增 sessionEpoch，丢弃旧身份在途响应，清空页面私有状态，再加载新身份数据。
退出清理：凭据、Cookie（若采用）、账号私有缓存与 Web 会话；不删除游客记录。
账号阅读元数据按账号隔离保留；提供“清除此账号本地记录”入口。

认证方式按站点支持情况验证：优先官方授权或用户自有 Token；原站网页登录只有在获准且会话接入可验证时采用。应用不自行收集社区密码，不假设两站都支持 OAuth。验证失败属于登录功能交付阻塞项，原站链接不能视为完成应用登录。

02 / 技术选型与边界

原生客户端

ArkTS + ArkUI 声明式界面；Navigation 管理路由栈，单 EntryAbility 起步。列表采用懒加载，正文按内容块渲染。

使用 DevEco Studio 当前稳定 SDK。项目启动时根据测试手机确认最低 API，再锁定工具链版本。

设备本地优先

关系型数据库保存主题、评论、稍后读和进度；Preferences 保存外观选项；图片缓存使用应用沙箱文件和 LRU 淘汰。

首版不建自有后端，不增加用户数据上传和服务运维成本。

站点能力隔离

通过适配器暴露阅读能力。认证、分页和正文格式分别转换；界面根据能力决定是否展示搜索、热门或登录入口。

不把两站能力强行取交集，也不展示无法完成的操作。

数据流

展示层FeedPage / TopicPage / DiscoverPage / LibraryPage / ReaderSettings
页面状态FeedStore / TopicStore → 加载中、成功、空结果、局部失败、过期缓存
业务与仓库TopicRepository / ProgressRepository / BookmarkRepository → 缓存优先，后台重验，按身份隔离
站点适配V2exAdapter / DiscourseAdapter → DTO 校验、分页转换、错误分类、能力声明
基础设施HttpClient · RdbStore · ImageCache · CredentialStore · Sanitizer · Logger

03 / 数据接入方案

接入点实施方式落地前验证
V2EX优先采用官方 API；v2 按官方 Bearer Token 契约接入。公开列表与热门来源单独验证，不假定 v2 覆盖所有首页能力。Token 获取、真实响应字段、配额、分页、正文与回复可见范围；缺失能力隐藏或提供原站入口。
Linux.do以 Discourse 官方接口模型设计适配器；主题列表和主题详情作为候选接入路径。站点开放性与登录策略必须实测。匿名可读分类、完整评论加载、限流、认证政策。Discourse 文档不代表 Linux.do 已允许所有接口。
认证首版必须验证游客与可选账号登录两条路径，由 SessionManager 按站点管理身份。敏感凭据使用系统密钥能力加密后保存在应用私有区，日志脱敏。不内置管理员 API Key；不借用服务端密钥实现客户端登录；不绕过访问挑战。
富文本HTML 解析为段落、标题、链接、图片、引用、代码等内容块；清理脚本、事件属性和不安全 URL。表格、长代码、表情、折叠内容、相对链接、引用关系与删除回复的降级展示。

优先安排接入验证作为第一道里程碑。若站点禁止第三方访问或要求暂时无法支持的认证，保留原站打开入口，明确标注支持范围；可选登录是首版要求，认证受阻需明确报告；互动功能另期实施。

核心接口草案（ArkTS 风格，需按锁定 SDK 编译适配）

type CommunityId = 'v2ex' | 'linuxdo';
interface PageCursor { value: string; }
interface TopicKey { site: CommunityId; id: string; }
interface PageResult<T> {
  items: T[];
  nextCursor?: PageCursor;
  hasMore: boolean;
}
interface CommunityCapabilities {
  latest: boolean;
  hot: boolean;
  search: boolean;
  authentication: boolean;
}
interface CommunityAdapter {
  capabilities: CommunityCapabilities;
  listTopics(query: FeedQuery): Promise<PageResult<TopicSummary>>;
  getTopic(key: TopicKey): Promise<TopicDetail>;
  listReplies(key: TopicKey, cursor?: PageCursor):
    Promise<PageResult<Reply>>;
}
// FeedQuery、TopicSummary、TopicDetail、Reply 在 domain/models 定义。
// UI 只依赖模型与仓库，不读取站点原始 DTO。

统一模型

Topic 使用 site + id 作为复合身份；保留 canonicalUrl、作者、分类、更新时间、内容块。Reply 保留原站 ID、楼层号、引用 ID 和作者标记。

进度锚点

记录 topicKey、正文/评论区、内容块或回复 ID、块内偏移和更新时间。恢复时优先稳定 ID，目标删除后退到最近可用位置。

分页语义

游标由站点适配器生成，页面不解析。Discourse 回复不能只读取首批 posts；按 post_stream 提供的 ID 补齐并去重，保持原顺序。

05 / 关键实现规则

场景编码策略验收条件
缓存更新先读数据库，展示缓存时间；后台拉取后事务写入再通知页面。无缓存且请求失败才展示整页错误。断网可读已缓存主题；刷新失败不清空内容。
切站与刷新竞态以 site + feed + category 区分状态，附带请求代次；过期响应丢弃，同页请求去重。快速切换站点不会混入另一站帖子；重复触底无重复条目。
网络错误区分离线、超时、401/403、404、429 和解析失败。限流遵守 Retry-After；仅对幂等读取做有限重试。登录限制与限流有明确提示，无无限重试。
正文与图片内容块稳定键、图片预留比例、按需解码；原图点击加载；长代码独立横向滚动。图片加载后正文不明显跳动；长文滚动不一次创建全部评论。
数据库topics、replies、feed_entries、bookmarks、reading_progress；联合主键隔离站点与 principalId；schema 版本迁移。HTML 渲染缓存带解析器版本。升级保留稍后读与阅读进度；迁移失败不静默清库。
缓存清理阅读历史与稍后读元数据独立保存；图片与正文缓存可按容量淘汰，设置页可清理。清缓存后收藏条目与进度仍在，离线正文可能需重新下载。
无障碍与返回主操作触控区域目标至少 48vp；语义标签、系统字体适配、安全区与系统返回一致。大字号无关键内容截断；返回列表保持滚动位置与筛选。

06 / 分阶段编码与交付

M0 · 接入与设备验证

创建原生空工程，锁定 SDK/API；用真实设备完成签名安装。分别验证两站列表、主题、分页、认证与访问限制，保存脱敏响应样本及能力矩阵。

出口：明确可支持功能；若接口受限，先完成原站打开和离线演示，不将其当成在线接入完成。

M1 · 纵向完成 V2EX 阅读

实现游客/登录状态与账号管理入口，接入已验证的 V2EX 认证；先写统一模型、网络层和 V2EX 映射；完成列表 → 主题 → 评论 → 返回位置的闭环，包含加载、空数据与失败状态。

出口：能在真机浏览实际内容，分页无重复，正文与评论可定位。

M2 · 本地连续阅读

实现数据库迁移、稍后读、进度锚点、离线缓存、字体与深色模式。补充恶意 HTML、超长内容、删除回复和离线场景测试。

出口：重启恢复进度；离线阅读已缓存主题；清缓存不丢稍后读。

M3 · Linux.do 与体验打磨

实现 Linux.do 独立登录与退出流程；按已验证能力实现 DiscourseAdapter，补齐完整回复流与引用展示；验证切站竞态、图片内存、长列表和系统返回。

出口：能力不支持时界面有清晰降级；账号可见内容不进入公共或共享缓存。

M4 · 安装包与使用说明

交付源码、依赖与 SDK 锁定说明、测试记录、开发签名 HAP 与真机安装步骤。按用户设备完成证书和调试授权配置。

开发签名包需要匹配调试设备；如需公开发布，再准备发布签名、应用元数据与商店审核材料。

07 / 验证清单与性能目标

自动化测试

用 Hypium 验证 DTO 映射、内容清理、游标终止、站点隔离、进度恢复和旧响应丢弃；使用脱敏固定样本，不依赖线上接口做单元测试。

真机验收

弱网/断网、系统返回、后台恢复、大字号、深色模式、图片浏览、长代码、千条回复主题、登录取消、游客转登录、账号切换、退出后私有缓存不可见、登录过期与 429。

测量目标

缓存列表可交互目标 ≤ 500ms；列表滚动目标 60fps；首批内容优先渲染。目标需在指定手机、构建类型和数据规模下记录实测，当前不是性能承诺。
